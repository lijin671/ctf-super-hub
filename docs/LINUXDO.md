# LinuxDo 社区说明

如果你的目标用户是中文用户，那么 GitHub 仓库之外，**LinuxDo** 很适合作为第二发布阵地。

## 推荐思路

- **GitHub**：作为主发布页、下载入口、文档中心
- **LinuxDo**：作为中文社区讨论页、反馈页、更新扩散页

也就是说：

> GitHub 负责展示与沉淀，LinuxDo 负责传播与互动。

## 推荐板块方向

### 1. 开发调优
适合：
- 项目发布
- 版本更新
- 功能介绍
- 截图 / 演示 / 设计说明

### 2. 资源荟萃
适合：
- 工具包分享
- skill 包整理
- 自动化脚本
- 说明文档合集

## 建议你在 LinuxDo 发什么

你可以直接围绕下面这几个点发：

1. 这是什么项目
2. 解决什么痛点
3. 为什么适合中文用户
4. 和普通 CTF skill 仓库有什么区别
5. 如何安装
6. 如何快速开始
7. 未来想加什么

## 可直接参考的发帖结构

```text
标题：
[开源自荐] CTF Super Hub：面向中文用户的 CTF / 逆向 Skills 整合包

正文结构：
1. 项目一句话介绍
2. 为什么做它
3. 核心功能
4. 适合谁
5. GitHub 地址
6. 快速开始
7. 欢迎提建议 / 提 issue / 点 star
```

## README 里怎么接 LinuxDo

建议你在 README 首页加这几个元素：

- LinuxDo 说明区
- LinuxDo 发帖链接（如果你已经发帖）
- 中文用户说明

例如：

- LinuxDo 发布帖：`待补充你的 LinuxDo 帖子链接`
- LinuxDo 讨论区：<https://linux.do>

## 最推荐的组合

- GitHub README：做成“发布页”风格
- LinuxDo 帖子：做成“中文传播页”风格

这两个配合起来，效果通常比只发 GitHub 更好。
